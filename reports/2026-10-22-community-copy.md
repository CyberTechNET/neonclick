# Тексты для подписчиков перестали быть слепой зоной

Дата: 22.10.2026. Правка: `tools/check-copy.cjs` (группа [8] и страж раскола),
`tools/negctl-copy.cjs` (роды контроля `mut` и раскол), `assets/community/guild-launch.md`
(два самоописания, ставших ложью).

## Дефект

`assets/community/guild-launch.md` появился в тот же день как материалы для стены и
комментариев: закреп, короткий пост, сторис, шесть шаблонов ответов, таблица
траблшутинга и чек-лист админа. В первых же строках он честно писал о себе:

> `npm run check:copy` сторожит досье, но не его, и единственная защита здесь —
> глаза плюс таблица соответствия.

Честно и плохо. Плохо не потому, что глаза ненадёжны, а потому, что файл держит те
же числа, которые сторожит группа [7]: ×1,25, 1000 монет, 5 чести = 15 минут,
2 обмена в сутки, звания 50/250/1000/5000/25000, таймаут 6 с. Все они — пересказ
`CFG.raid`, `CFG.boost.mult` и `T_GUILD`, и колонка «Источник» в §7 файла подписывает
это прямо, полями вроде `CFG.raid.guildMult` и `T_GUILD`. Значит, правка баланса делает пост
неправдой — тем же классом лжи, ради которого `check:copy` и существует, только
адресатом выступает не модератор кабинета, а подписчик с телефоном.

Второй разрыв был рядом: запрет на обещания (`PROMISE`) жил внутри блока [7] и мерил
витрину, а стену — нет. Правило «не обещай удачу, выигрыш и деньги» оказалось
наполовину действующим: наполовину, где его проверяют.

## Что сделано

Группа [8] в `tools/check-copy.cjs` — 29 проверок, значения для которых читаются из
кода, а не переписываются в чекер:

| Что сверяется | Откуда число |
|---|---|
| надбавка «×1,25 к чести недели» | `CFG.raid.guildMult`, с запятой вместо точки |
| «1000 монет … = 1 честь» | `CFG.raid.honorPer` |
| «5 чести = 15 минут» | `CFG.raid.boostCost`, `CFG.raid.boostMs` |
| «2 обменов в сутки» | `CFG.raid.perDay` |
| цепочка «Новобранец 50 → … → Гроза рейда 25000» | `CFG.raid.tiers` |
| множитель буста «×2» | `CFG.boost.mult` |
| «таймаут 6 с» | `T_GUILD` в `vk-integration.js` |
| имя сообщества в тексте | `CFG.guild.roster[0].name` |
| ссылка запуска и ловушка со знаком | канон из README п.3 |
| шесть подписей состояний | ветки вкладки «Гильдия» в `game.js` |
| «id гильдии переживает переустановку» | `S.gid` в сейве и `d.gid` в `packCloud` |
| колонка «Источник» §7 | существование каждого идентификатора в названом файле |
| отсутствие обещаний в цитатах и таблицах | `PROMISE`, поднятый на уровень модуля |
| ни одного расколотого числа | множество ВСЕХ значений при каждой единице |
| невыезд наружу | наличие файла в `FOREIGN` у `.release-check.cjs` |

Три решения внутри группы:

1. **Ни одного номера в чекере.** Ссылка запуска вычитывается из README п.3, а не
   заводится вторым экземпляром: номер карточки уже менялся (54836005 → 54839632),
   и второй экземпляр переживает такую смену молча — то есть врёт. Отдельная
   проверка требует, чтобы во всех текстах сообщества номер карточки был ровно один,
   — копипаста отозванной карточки краснеет здесь, а не под постом.
2. **Обе стороны подписей состояний.** Таблица траблшутинга первой колонкой цитирует
   интерфейс. Проверяется и то, что игра рисует каждую названную подпись, и то, что
   материалы её называют теми же словами: правка, прошедшая только со стороны кода,
   постом не замечается, и наоборот.
3. **`PROMISE` поднят на уровень модуля.** Держать его внутри [7] значило бы
   переписать во второй группе, а переписанное правило расходится с оригиналом
   ровно в ту сторону, где обещание уже напечатано.
## Пустой проход, найденный по дороге

Первая версия группы [8] прочитала `CFG.raid` регулярками, начинавшимися с
ограничителя `(^|[,{\s])`. `m[1]` возвращал ограничитель, а не значение, поэтому
пять чисел стали пустыми строками. Итог:

```
❌ надбавка названа тем же числом, что CFG.raid.guildMult (×0)
❌ обмен назван парой чисел из CFG.raid.boostCost/boostMs ( чести = 0 мин)
✅ курс чести совпадает с CFG.raid.honorPer ( монет = 1 честь)
✅ потолок обменов в сутки — CFG.raid.perDay ()
✅ цепочка званий совпадает с CFG.raid.tiers и по порогам, и по именам
```

Две проверки покраснели, три прошли молча: `cd.includes('' + ' монет')` истинно на
любом документе. Регулярка умерла тихо, и сторож, который должен ловить расхождение
чисел, превратился в украшение — ровно тот класс отказа, ради которого существует
`check:negctl`. Лечится не только исправлением `m[1] → m[m.length - 1]`, но и
стражем самого себя, который теперь стоит первым в группе:

```js
ok([guildMult, honorPer, boostCost, boostMin, perDay].every((n) => Number.isFinite(n) && n > 0),
  'все числа CFG.raid прочитаны числами, а не пустым захватом', { ... });
```

Пока число не стало числом, сверять с ним текст бессмысленно, и эти строки не дают
пустому захвату пройти дальше.

## Род контроля `mut`

`tools/negctl-copy.cjs` умел только вырезать абзац (`cut`). Для сторожей, сверяющих
документ с CFG, вырезание бесполезно: правило «в тексте есть ×1,25» остаётся истинным,
пока в тексте живёт слово «честь» и строка таблицы §7. Поэтому в цикле прогона
появился второй род — подмена цифры во **всех** её вхождениях (`/g`):

```js
{ name: 'сообщество: надбавка ×1,25 — это CFG.raid.guildMult',
  file: COMM, mut: [/×1,25/g, '×1,35'],
  rule: (t) => t.includes('×1,25 к чести недели') }
```

Глобальность мишени — часть метода: одиночная замена оставила бы второе вхождение в
таблице §7, правило осталось бы истинным, и контроль был бы засчитан как мёртвый.
Если CFG поменяет значение, подмена не найдёт старую цифру и контроль сам покраснеет
как слепой — это и есть сигнал обновить пару «документ ↔ контроль».

Исключение — контроль запретов: там мишенью служит вставка обещания («Испытай удачу
и …») в строку закрепа, потому что вырезать нечего — правило отрицательное.

## Раскол: что живая дрейф-проба нашла в первом варианте

Когда группа позеленела, был снят не только синтетический контроль (`negctl`), но и
живой: правка настоящего документа, прогон, восстановление. Первая партия — четыре
дрейфа: обещание в закрепе, ссылка без минуса, `CFG.raid.perDay` в коде и подмена
надбавки. Три покраснели, четвёртый молчал:

```
МОЛЧАЛ   документ: надбавка РАСКОЛОТА (одно вхождение)   ===== ТЕКСТЫ ВИТРИНЫ 147 ok / 0 fail =====
```

Подмена `×1,25` → `×1,35` только в первом вхождении. После неё закреп обещает
подписчику ×1,35, сторис по-прежнему ×1,25, а `cd.includes('×1,25 к чести недели')`
удовлетворена выжившим вхождением. Ровно тот класс лжи, ради которого группа и
существует: половина текста неправда, а прогон зелёный.

Показательно, почему `check:negctl` этого не поймал: его контроль для той же надбавки
подменяет цифру глобально (`/g`) — он сильнее сторожа, а не слабее. Обычный страх —
сторож сильнее контроля, и тогда контроль льстит; здесь вышло наоборот, и ни один из
двух инструментов не был в одиночку виноват.

Лечится стражем раскола: для каждой единицы берётся множество ВСЕХ чисел рядом с ней и
оно обязано состоять ровно из значения CFG.

```js
const unit = (re, want, what) => {
  const seen = [...new Set([...spoken.matchAll(re)].map((m) => m[1]))];
  ok(seen.length > 0 && seen.every((v) => v === String(want)), what + …, seen);
};
unit(/(\d+)\s*монет/g, honorPer, 'курс чести');          // …
const printed = […×-токены spoken…];                    // = {guildMult, boost.mult}
```

Шесть единиц (монеты, честь за неделю, стоимость обмена, длительность буста, потолок
обменов, таймаут) плюс множество множителей — семь проверок. Скоуп — `spoken`, строки
цитаты и таблицы, а не весь файл. Это не аккуратность, а необходимость, и выяснилось
из перечисления, а не из догадки: проза самого файла называет спорные числа как
перечень — «подмена надбавки на ×1,35 … красят контроль» и заголовок «Чек-лист админа
перед анонсом (2 минуты)». Мерить прозу тем же правилом значит заставлять её краснеть
там, где она говорит правду.

Вторую ошибку нашёл сам страж, ещё до прогона: `/= (\d+) честь\b/` не матчит ничего,
потому что `\b` опирается на `\w` = `[A-Za-z0-9_]`, а «ь» и пробел — оба не-символьные,
границы нет. Проверка читалась как «факта нет в тексте» и краснела на здоровом
документе. Урок, уже записанный в шапке `negctl-copy.cjs` и ставший причиной его
существования, был повторён в новом коде буквально через час — что и оправдывает
отдельный прогон контроля вместо веры в регэксп.

Итоговая батарея, 16 мутаций → 16 красных, 0 молчаливых; файлы восстановлены:

| Дрейф | Что краснеет |
|---|---|
| надбавка во всех вхождениях | `includes` по `CFG.raid.guildMult` |
| надбавка расколота (одно вхождение) | множество множителей |
| курс чести расколот | `unit(монет)` |
| стоимость обмена расколота | `unit(чести =)` |
| длительность буста расколота | `unit(минут)` |
| потолок обменов | `includes` + `unit(обменов в сутки)` |
| таймаут | `unit(таймаут N с)` |
| обещание в закрепе | `PROMISE` по `spoken` |
| ссылка без минуса | канон + ловушка со знаком |
| звание переименовано | цепочка `CFG.raid.tiers` |
| имя сообщества чужое | `CFG.guild.roster[0].name` |
| `CFG.raid.perDay` 2 → 3 | `includes` + `unit` |
| `CFG.raid.guildMult` 1.25 → 1.3 | `includes` + множество множителей |
| подпись состояния переименована | `ghostLabels` |
| `T_GUILD` 6000 → 8000 | `unit(таймаут)` |
| `gid` убран из `packCloud` | обещание про переустановку |

Два контроля раскола добавлены в `negctl-copy.cjs` намеренно без `/g`: они меряют не
отсутствие числа, а половину лжи, и противоречат правилу «мишень глобальная» ровно
настолько, насколько правы.

## Что правке не подчинилось

- Тексты постов по-прежнему пишет человек: автомат сверяет числа, имена и запреты,
  но не смысл и не тон.
- Длина постов не ограничена ничем: публичного лимита на запись стены у VK нет, а
  выдумывать бюджет — значит через месяц краснеть на собственный регэксп.
- §6 (чек-лист админа) не проверяется: это процедура, а не факты о продукте. Кроме
  ссылки запуска — она попадает под общее правило.
- Скриншот вкладки «Гильдия» по-прежнему требует живого сообщества: его нельзя снять
  из мока, и это единственная позиция комплекта, которая физически не может быть
  готова до добавления приложения в сообщество.
- `assets/community/` пока состоит из одного файла, и `FOREIGN` в `.release-check.cjs`
  перечисляет его поимённо — как и `assets/moderation/`. Второй файл обязан быть
  дописан в тот же список в том же коммите, иначе проверка «чужих файлов на хостинге
  нет» про него просто не узнает.
- Правка лежит в рабочем дереве: `main` опережает `origin/main`, а Pages публикует
  `_site`, собранный Actions из `main`. До пуша развёрнутая игра и превью админки VK
  показывают прежнюю монету и прежнюю подсказку вкладки «Гильдия».
