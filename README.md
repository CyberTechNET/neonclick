# NEON CLICK — VK Mini App

Кликер на чистом HTML/CSS/JS без сборки, фреймворков и бэкенда. Раздаётся как
статика, живёт внутри клиента ВКонтакте как мини-приложение.

## Что публикуется

Боевой артефакт — **пять файлов**, и только они должны лежать на хостинге:

| Файл | Роль |
|---|---|
| `index.html` | разметка; подключает три ресурса ниже с `?v=<hash>` |
| `style.css` | витрина и темы |
| `game.js` | вся игровая логика, античит, сейвы |
| `vk-integration.js` | мост в VK: SDK, реклама, репосты, облако, гильдия |
| `vk-bridge.3.0.2.js` | вендоренный `@vkontakte/vk-bridge` (см. `tools/vendor.json`) |

Всё остальное дерево — внутренняя кухня: наборы проверок (`.smoke-test.cjs`,
`.vk-mock-check.cjs`, `.visual-check.cjs`, `.stress-check.cjs`,
`.release-check.cjs`), эталонные прогоны (`base_*.txt`), `package.json`,
`tools/`. На хостинг они не попадают **механически**, а не по внимательности:
Pages публикует не ветку, а артефакт, собранный `tools/build-release.cjs`
из allowlist (см. `.github/workflows/deploy.yml`). Это важно, потому что
сайт на Pages открывается всем, даже когда репозиторий приватный.

## Сборка артефакта

```
npm run build:release        # → _site/ (в .gitignore)
```

Сборщик делает ровно три вещи и останавливается, если хоть одна не удалась:

1. **Вырезает отладочный хук.** В репозитории `?debug=1` создаёт `window.NEON`
   (`tap`, `add`, `state`, сдвиг часов, темы) — на нём висят четыре набора
   проверок, поэтому из исходника хук удалять нельзя. В публикуемом файле его
   нет: регион между маркерами `RELEASE-STRIP` убирается целиком, а
   `const DEBUG = …` заменяется на `const DEBUG = false;`. Второе важнее, чем
   кажется: тем же флагом выключается **потолок правдоподобия** в античите
   (`game.js`, `if (!legacyT0 && !DEBUG)`), так что в публикации он активен
   всегда. Постусловия проверяются по готовым байтам (`window.NEON` отсутствует,
   маркеров нет, `node --check` проходит), а не по факту срабатывания регэкспа.
2. **Ставит cache-bust.** Каждому локальному ресурсу в `index.html` добавляется
   `?v=<8 hex>` — первые 8 символов sha256 от конечных байтов файла. Без этого
   WebView VK и кеш Pages держат старую игру после хотфикса. Хэш по содержанию,
   а не по SHA коммита: сборка одного и того же исходника бита в биту одинакова,
   и кеш браузера не сбрасывается впустую.
3. **Сверляет вендор.** `vk-bridge.3.0.2.js` сверяется с `tools/vendor.json`
   по размеру и sha256, из него вырезается ссылка на несуществующий `.map`,
   а `SDK_LOCAL` в `vk-integration.js` проверяется на совпадение с именем файла.

Зависимостей у сборщика нет (только `node:fs/crypto/child_process`), поэтому
серверная сборка не ставит `jsdom` и `puppeteer-core` — они нужны лишь локальным
прогонам.

## Как это выкладывается

`git push` в `main` → GitHub Actions (`deploy-pages`) собирает `_site` и
публикует его на Pages. Источник публикации — **GitHub Actions**, а не ветка:
так Jekyll не трогает файлы, и на сервер не уезжает лишнее. Адрес:
`https://<логин>.github.io/<репозиторий>/`.

Первая настройка (однократно):

```
gh repo create <логин>/<репо> --private --source=. --push
gh api repos/<логин>/<репо>/pages -X POST -f build_type=workflow
```

Приватный репозиторий здесь не косметика: история коммитов хранит наборы
проверок и их эталонные прогоны, а наружу смотрит только собранный артефакт.
Pages на приватном репозитории доступен аккаунтам GitHub Pro/Team; на Free
репозиторий приходится делать публичным — тогда наборы проверок и `base_*.txt`
уезжают в историю вместе с ним, и об этом стоит подумать заранее.

## Проверка

| Набор | Против чего | Пользуется хуком | Что закрывает |
|---|---|---|---|
| `.smoke-test.cjs` | jsdom, файлы репозитория | да | разметка, id и классы, игровая математика, темы, параметры запуска VK |
| `.vk-mock-check.cjs` | Chromium + стенд 5173 | да | сцены VK Bridge: реклама, репосты, гильдия, облако |
| `.visual-check.cjs` | Chromium + стенд 5173 | да | геометрия, хит-тесты, палитры тем, скриншоты |
| `.stress-check.cjs` | Chromium + стенд 5173 | да | нагрузка, правки сейва, виртуальные часы, облако, утечки памяти |
| `.release-check.cjs` | **боевой URL**, без мока | **нет** | чёрный ящик по публикации |

Стенд для первых четырёх: `python -m http.server 5173` (или Live Server в
VS Code — тогда `$env:NEON_BASE = 'http://127.0.0.1:5500'`, переписывать код
наборов не требуется).

Первые четыре набора требуют хук и потому гоняются **только по дереву
репозитория**: в опубликованной игре хука нет by construction, и это проверяемое
утверждение, а не неудобство. Пятый устроен наоборот — он не знает про `NEON`,
тапает мышью, читает `localStorage` и сеть, и потому единственный работает по
боевому URL:

```
npm run build:release
npm run serve:release                                          # стенд _site на 5173
$env:NEON_BASE = 'http://127.0.0.1:5173'; node .release-check.cjs      # прогон локально
$env:NEON_BASE = 'https://<логин>.github.io/<репо>'; node .release-check.cjs   # по публикации
```

Он закрывает три пробела, которых не видит ни один локальный прогон: реальный
HTTPS-хост вместо 127.0.0.1 (TLS, редиректы Pages, кеш Fastly и относительные
пути на **подкаталоге** `/reponame/`, где `/game.js` уже не существует);
загрузку настоящего `vk-bridge` без предподставленного мока; и состав хостинга
(пять файлов отвечают 200, `package.json`, наборы проверок и `.git` — нет).
Плюс два главных утверждения публикации: `?debug=1` не создаёт `window.NEON`,
а 999999, вписанные в `localStorage` руками, не доживают до HUD.

Полный прогон перед выкладкой:

```
npm test                                                # сборка + четыре набора
$env:NEON_BASE = 'https://…'; node .release-check.cjs   # пятый — по публикации
```

## Хотфикс

Правим исходники → `npm test` → `git commit` → `git push`. Версии `?v=` меняются
сами по содержанию файлов. Старый кеш WebView не оставит игрока в промежуточном
состоянии: артефакт выкладывается целым каталогом, поэтому либо все пять файлов
новые, либо ни одного.

## Кабинет VK: что делается руками

1. Создать мини-приложение (dev.vk.com → Мои приложения), получить `vk_app_id`.
2. Настройки → Размещение → вписать URL публикации в **три** поля: десктоп,
   мобильная версия сайта (`m.vk.com`), мобильное приложение. После этого
   прогнать `.release-check.cjs` с `NEON_BASE` по этому URL.
3. Добавить это же приложение как приложение сообщества — иначе вкладка
   «Гильдия» не оживёт: `vk_group_id` приезжает только из папки сообщества.
4. Подключить кабинет VK Ads и оформить точки монетизации: rewarded-ролик
   (`VKWebAppShowNativeAds` с `ad_format: 'reward'`) и репост. Пока кабинет не
   подключён, `VKWebAppCheckNativeAds` отвечает пусто и точка наград остаётся
   неактивной — игра при этом не ломается, это штатная ветка.
5. Держать «Состояние для пользователей» = Выключено, пока идёт обкатка: по
   умолчанию приложение видно только создателю и администраторам по
   `vk.com/app{ID}`; для проверки на чужом телефоне добавляем тестировщиков в
   разделе «Тестирование». Включать перед модерацией.
6. Собрать материалы модерации: иконка, скриншоты, категория, возрастная
   маркировка, политика конфиденциальности. В репозитории их нет — это
   отдельные файлы, и без них заявку не примут.

## Известные ограничения

- **Идентификаторы читаются через `parseInt`** (`vk-integration.js`:
  `vk_group_id`, `group_id`, `gid`). Пока VK привозит числа — всё в порядке.
  Переход на LongID, о котором предупреждает VK, означает, что нечисловой id
  даст `NaN → 0 → guildLaunch() === null`, и вкладка «Гильдия» тихо исчезнет.
  Монетизация от этого не пострадает, но замечать такое надо по факту, поэтому
  пункт здесь.
- **Подпись сейва клиентская** (`SIGN_SALT` в `game.js`). Она отрезвляет ручную
  правку и копит «подозрительность», но не может быть криптозащитой для того, у
  кого есть доступ к байтам игры. Серверной проверки прогресса нет намеренно:
  бэкенда в этом проекте нет вообще.
- **Домены `vk.ru` и `m.vk.ru`.** VK советует добавлять их в доверенные, если
  приложение проверяет происхождение запросов. Мы не проверяем ничего
  (`origin` в релизных файлах встречается только как CSS `transform-origin`),
  поэтому оба домена работают из коробки.
- **Приватный режим WebView** режет `localStorage`: все обращения к нему в
  `game.js` обёрнуты в `try/catch`, а прогресс дублируется в облако VK
  (`VKWebAppStorageSet/Get`, лимит 4096 символов на значение).
